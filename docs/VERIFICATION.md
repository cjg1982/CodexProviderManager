## 发现并修复的问题

| 原问题 | 本次处理 |
| --- | --- |
| 文档包含作者本机绝对路径 | 改为项目根目录执行的通用说明，重新打包源码 |
| 保存 Key 的 CLI 参数写法无法正确接收标准输入 | 改用 Security.framework 写入，保留固定 security 命令读取方式 |
| 切换和恢复时删除所有供应商定义 | 只替换同 ID 供应商；恢复仅移除顶层选择，保留未使用的定义 |
| 测试自动加 `/v1`，配置写入却不加 | 共用 URL 规范化规则，自定义 API 路径原样保留 |
| 同名资料生成相同供应商 ID；可使用内置保留 ID | 新资料 ID 加唯一后缀，校验保留名称和重复 ID |
| 200 响应即视为 API 可用 | 校验模型列表结构；Responses 要求 completed、有效 ID 和非空 output |
| 写死某一应用中的 CLI 路径，忽略 CODEX_HOME | 查找常见安装位置，支持 CLI 路径覆盖和自定义 Codex 目录 |
| 带引号的配置键、CRLF 等可能识别错误 | 改进局部 TOML 编辑，测试带引号的键、表名、转义和多行字符串 |
| 命名 profile 可能覆盖切换结果 | 顶层启用 profile 时明确拒绝切换；文档说明外部覆盖项 |
| 空文件未备份；并发编辑检测不足 | 备份已有空文件，写入前复核快照，拒绝覆盖并发修改，锁路径不跟随符号链接 |
| 输入 Key 后自动联网；应用时可能用到未保存旧值 | 改为明确点击后请求，应用前检查未保存改动，Responses 测试使用表单当前值 |
| 导入已保存资料改变资料 ID，导入失败后内存状态不一致 | 保留原资料 ID，保存失败恢复内存状态 |
| 旧包可能与源码不一致 | 提供统一 release.sh 和源码白名单打包脚本，生成校验文件 |

## 自动测试范围

- 配置插入、恢复、重复恢复、多供应商保留、替换同 ID 表和认证子表。
- 注释、引号、转义、多行值、CRLF、相似表名及嵌套键。
- 无效地址、远程明文 HTTP、嵌入账号、查询参数、具体接口路径与保留供应商 ID。
- 配置备份、0600 文件权限、失败回滚、原文件缺失或为空、符号链接拒绝、并发修改保护。
- 资料读写、重复 ID 拒绝、无预置供应商及 JSON 不包含 Key 字段。
- 大量标准输出与标准错误不死锁、进程超时。
- 临时钥匙串的真实系统读写；模拟 HTTP 成功、格式错误、失败 / incomplete 状态、认证错误和超大响应。
- 在临时 CODEX_HOME 中用实际 Codex CLI 确认生成配置的 `config.load` 状态为 `ok`。

## 尚未验证的部分

- 没有使用个人 Key 或第三方付费服务做端到端生成测试；供应商的模型权限、计费、流式输出、工具调用、长上下文和服务稳定性需要用户自行验证。
- 没有完成所有界面操作及客户端重启后的人工验收；也没有验证已有会话是否会切换供应商。
- 只验证了上述本机环境；macOS 11 最低版本、其他系统版本、Intel Mac 和旧版 Codex CLI 尚未实机验证。
- 只修改用户默认配置，不管理命令行 `--profile` / `-c`、管理员策略或启动环境覆盖。编辑器是局部编辑器，不是完整 TOML 实现；不支持的写法可能被拒绝或在 CLI 验证时回滚。
- 钥匙串访问控制使用经典 macOS Keychain API；编译器会提示 `SecTrustedApplicationCreateFromPath` 已弃用。当前环境的隔离测试通过，后续系统升级仍需回归验证。
- 应用只有 ad-hoc 签名，没有 Developer ID 签名或 Apple 公证。

## 个人信息检查

检查源码、文档、现有应用和旧压缩包时未发现硬编码的真实 API Key 或私人 API 服务地址；发现 README 及旧源码包包含本机用户名路径，已从发布源码中移除。最终源码包通过白名单生成，不打包真实 Codex 配置、auth.json、钥匙串、供应商资料、配置备份、.git 或 .DS_Store。

此类模式扫描只能识别已覆盖的凭据形态，不能证明不存在任何未知格式的敏感信息。应用运行时的个人资料和钥匙串不属于源码发布内容，也未被删除。
